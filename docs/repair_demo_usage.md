## 启动独立 Mock 演示

在主仓库 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_repair_demo.py
```

脚本创建新的随机命名 SQLite 数据库，仅对这个新库执行迁移和 Demo 初始化。打开 `http://127.0.0.1:5002/ai-test-design/`。

Demo 登录：`demo@example.com` / `demo-password`。

关闭后重新启动同一演示：在原命令末尾加 `--database repair-demo-实际编号.sqlite`，使用首次启动打印的文件名。重启不执行迁移或 Seed，保留审核和用例。`--prepare-only` 只准备新库、不启动服务器；`--port 5003` 可选其他本地端口。

脚本固定 Mock、清空应用 Provider Key、不加载 `.env`、关闭 debug/reloader、仅监听回环地址。它不支持真实 API 模式。不要用主仓库旧数据库或正式实验库替换演示库。

## 人工验收步骤

1. 登录后打开 AI Test Design → New Session，选择已有 Demo Project 及对应 Version。
2. 标题填 `Demo 音量调节`；需求填 `Demo 耳机音量范围为 0 到 100。调整后界面显示当前音量，超出范围时提示错误。所有设备和账号均为虚构测试数据。`
3. 确认页面明确显示 Mock，点击生成。生成中按钮禁用并提示等待；不要把 Mock 输出当成真实模型效果。
4. 打开草稿，编辑标题/步骤并保存；接受一条、拒绝另一条。接受后正式 TestCase 的业务状态仍为 draft，并非已经执行通过。
5. 查看生成记录、审核记录和正式用例；刷新后结果应一致。
6. 关闭服务后带同一数据库文件名重新启动，确认编辑、审核和正式用例仍在。
7. 打开同一草稿的两个编辑页面；第一个保存后，第二个旧页面保存应提示冲突，不能覆盖第一份内容。点击“重新加载”取得当前版本。

其他管理功能通过原有 Project、Version、TestCase、Execution、Defect、Dashboard 入口使用，数据均在该独立演示库。

## 状态与错误

- 同一个请求键的成功重放返回原批次；失败请求键不自动重试。
- 正常 Provider/Schema/持久化失败显示错误，并提供运行记录入口；用户确认后可新建请求。
- 运行记录页只查询，不重新调用模型。诊断仅保存允许的阶段、类别与字段路径，不保存未经审查的失败原文。
- 进程中断或终态保存失败时，Run 保留 running / 结果待确认，同内容的活动锁保持。当前版本没有自动解锁或人工恢复按钮；需确认原进程与调用结果后再由维护者针对该新 Web Run 处理。不能据等待时间推定失败或修改实验 #43。
- 新增迁移为 `e8f3a7c1d902`，已在两个旧数据库的独立副本上验证升级、逐行历史值保留及完整性。旧库原件未迁移；不要直接用默认旧库启动新代码。演示使用上述新库或已验证的独立升级副本。
- 此迁移不支持降级。需要回滚时，先停止服务并保留新库，再逐文件恢复合入前代码，配回原版本数据库；不得用旧代码直接打开升级库或执行降级迁移。
