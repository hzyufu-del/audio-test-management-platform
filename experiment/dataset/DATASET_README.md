# 虚构软件需求实验数据集

## 用途与状态

本数据集供本科毕业设计《基于大语言模型的智能测试用例生成与管理系统设计与实现》的后续对照实验使用，配合 [实验方案](../../docs/experiment-design.md) 比较普通 LLM 生成与当前系统方法的场景覆盖、人工修改负担及工程表现。

- 数据集版本：**v1.0**。
- 制作日期：2026-10-02。
- 当前状态：**材料已制作，未用于正式实验**。本阶段没有运行生成实验、调用 DeepSeek 或其他外部 LLM API，也没有导入数据库。
- 正式运行前仍需由实验方案指定的两名实际评价人员复核需求与参考点并冻结版本。本轮静态检查和代码代理校对不等于实际人员评价或实验结果。

## 数据来源与边界

数据来源采用**人工设计虚构需求**的方案：依据已确定的分类、规模和业务规则约束，由 Codex 辅助起草、整理并做静态一致性校对。此说明保留制作工具来源，不将辅助起草声称为已完成的真人独立设计或审核。

所有题材均为虚构 Demo 学习空间、资料目录、材料预约或配置页面。没有使用公司需求、实习项目、商业系统数据、日志、缺陷数据或已有 TestCase；没有查询或复制现有业务数据库，也没有使用项目 Provider 自动生成材料。

这些需求描述假设的被测功能，不表示当前测试管理系统已实现资料搜索、预约业务或文件上传等被测模块。上传需求只定义虚构文件元数据的验收，不包含实际文件；身份校验只描述长度、匹配关系和状态，不包含账号校验材料或验证码字面值。

## 文件及格式

| 文件 | 内容 | 记录数 |
| --- | --- | ---: |
| requirements.jsonl | 需求、明确规则及约束 | 28 |
| reference_scenarios.jsonl | 独立评价用参考场景点 | 168 |
| DATASET_README.md | 来源、统计、字段及使用约定 | — |

两个 JSONL 文件采用 UTF-8、无 BOM，每个物理行是一个完整 JSON 对象，文件末尾保留换行，没有空白数据行。requirement_text 内部的规则换行编码为 JSON 字符串中的 \n，不额外拆分记录。

需求字段为 requirement_id、dataset_version、category、title、requirement_text、business_rules、input_constraints、exception_conditions、boundary_conditions。正文包含功能描述及四组规则的完整原句，数组用于定位、核对和结构化查看；不需要在正文之外补充业务前提。

参考点字段为 requirement_id、point_id、scenario_type、trigger_condition、expected_behavior、requirement_basis。requirement_basis 保存所引用的完整编号规则原句，能够在对应需求正文和规则数组中直接查到。参考点是评价标准，不是已执行测试用例或运行结果。

| 类别 | 编号前缀 | 需求数 | 参考点数 |
| --- | --- | ---: | ---: |
| 用户认证 | REQ_AUTH | 4 | 24 |
| 信息管理 | REQ_INFO | 4 | 24 |
| 查询搜索 | REQ_SEARCH | 4 | 24 |
| 文件上传 | REQ_FILE | 4 | 24 |
| 权限管理 | REQ_PERM | 4 | 24 |
| 订单流程 | REQ_ORDER | 4 | 24 |
| 系统设置 | REQ_SETTING | 4 | 24 |
| **合计** | — | **28** | **168** |

每类需求按 001～004 编号，requirement_id 全集唯一；例如 REQ_AUTH_001、REQ_FILE_001。编号已稳定分配，后续实验不得重排、复用或临时改号。

每条需求固定 6 个参考点：

| point_id 后缀 | scenario_type | 每需求数量 | 全集数量 |
| --- | --- | ---: | ---: |
| P01、P02 | normal | 2 | 56 |
| P03、P04 | negative | 2 | 56 |
| P05、P06 | boundary | 2 | 56 |

point_id 格式为“requirement_id + _P01～_P06”，全局唯一。边界场景包括合法端点、临界前后值或数量阈值；boundary 标签不表示该点必然成功，须以 expected_behavior 判断。

## 使用与复核约定

1. 后续两种方法只接收相同的 title 和 requirement_text。规则数组已经完整写入正文，不再拼接以造成重复；**reference_scenarios.jsonl 不提供给任何生成方法**。
2. 场景彼此独立，不继承上一个参考点执行后的状态。触发条件中的虚构现有对象、数量、时间和归属是该场景的前置条件，不对应真实数据库记录。
3. 文本长度按 Unicode 字符计数，标点、空格和换行也计入；字符限制不是 UTF-8 字节长度。每条需求若需要去除输入首尾空白，会在其自身规则中说明。
4. 文件大小使用字节，1 KiB=1,024 字节、1 MiB=1,048,576 字节；像素、模拟秒/分钟/天和积分均使用需求中明确的单位。
5. 每个参考点仅设置所指明的异常或边界，其他输入满足该条需求；多项非法条件同时发生时的报错优先级不属于 v1.0 的参考点范围。
6. 参考点必须依据触发条件、可执行步骤和预期行为判断覆盖，不能只根据生成用例的 normal/negative/boundary 标签计分。多个用例命中同一点仍只计一次。
7. 六个参考点是冻结后的覆盖评价分母，不声称穷尽该功能的所有测试场景。参考之外的合理场景可另记备注，不临时扩大或缩小分母。
8. 正式实验前如发现语义问题，应先修订并登记新的数据版本；正式实验运行后不修改输入或参考标准以适配生成结果。稳定 ID 与版本共同标识记录，旧版本不得静默替换。
